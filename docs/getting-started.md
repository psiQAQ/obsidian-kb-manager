# 安装与创建第一个知识库

桌面版需要 Obsidian 1.15.1 或更高版本和系统 Git。模板已随插件打包。运行模板专项、已授权的自定义通用规则或离线命令行入口时，需要能从系统 PATH 找到的 Node.js。安装与建库均可离线完成。

## 手动安装插件

1. 在同一版本的 **Assets** 中下载 `main.js`、`manifest.json` 和 `styles.css`。[GitHub Releases](https://github.com/psiQAQ/obsidian-kb-manager/releases/latest)
2. 将三个文件放入目标 Vault 的 `.obsidian/plugins/knowledge-base-manager/`。若自定义了 Vault 配置目录，使用该目录下的 `plugins/knowledge-base-manager/`。
3. 重新加载 Obsidian，在 **设置 → 第三方插件** 中启用 **Knowledge Base Manager**。打开左侧书架图标，或运行命令 **打开知识库管理器**。

## 用「光学研究」试建一个库

1. 在管理器点 **新建**，选择 **AI 协作 → 融合 LLM Wiki → 填写知识库信息**。内置模板有 9 个用途、18 套。已登记的个人目录也出现在 **我的模板** 中，模板详情页列出入口、来源和声明的工作流依赖。[模板目录](template-catalog.md)
2. 在详情页打开 **目标父目录 → 浏览…**。要直接建在 Vault 中，在 **浏览目录** 页确认根目录，然后在 **目录名** 填「光学研究」。**仓库内位置** 应显示 `光学研究/`。显示名留空时使用目录名。要建在 `课题/光学研究/`，点击「课题」目录行再确认。也可切到 **输入路径** 填入尚不存在的父目录；配置了可用收藏时还会显示 **收藏目录**。取消选址会保留上次确认的位置。
3. 在 **高级 Git 选项** 核对姓名、邮箱、初始分支和首提交说明。向导预填全局 Git 配置，姓名缺失时取系统登录名；邮箱缺失时先检查 `EMAIL`，再使用 `登录名@users.invalid` 形式的占位地址。占位邮箱也会进入提交历史。如需关联 GitHub 账号，请填已验证邮箱或自己的 GitHub noreply 地址。你在向导里修改的字段及设备提供的兜底值写入本库 Git 配置，全局提供的值继续继承。

**origin 远端地址** 可留空。桌面接受 HTTPS、`ssh://` 和 `git@host:path`。填写地址只配置本库。选择 **预览**，核对目标 `光学研究`、作者与提交者、初始分支、提交说明、远端、提交文件和排除项，需要修改时选择 **返回详情**，核对无误后点 **创建知识库**。初始分支和首提交说明可在建库时修改。沿用默认值会在 `main` 分支创建 `Initial commit`。在 Git 历史中可查看它的短 SHA。本例中的页面模板已纳入版本管理，`kb.toml` 随库保存在本机。克隆、导入和接管已有库会沿用已有历史。若目标路径的 Git 配置改变了身份，或提交后登记未完成，使用当前向导中的复核按钮检查目标目录、身份和 HEAD 后继续。关闭 Obsidian 后仍可通过库内的 `kb.toml` 登记已经完成首次提交的库。

若预览提示检验排除规则指定的路径在新库中缺失，请核对模板 `kb-template.json` 内的实际路径和大小写。创建成功后点 **运行首次检验**，查看默认的通用检验和模板专项结果。个人模板的专项脚本需要审查并授权对应版本后才能运行。

## 插入本库页面模板

融合库通过链接维护索引，并提供逐次记录摄入、保存、归档或体检的操作日志模板。本库 `Templates/` 有 7 个页面模板和 1 个分类 Base 样板。Kepano 有 52 个页面模板和 30 个按实例筛选的 Base。两者均在首次提交中写入 `.gitattributes`，使 Markdown 以 LF 换行检出，附件沿用原 Git 行为。

打开库内的 Markdown 笔记，运行 **插入本库页面模板**，选择模板后核对目标、属性和插入预览。已有同名属性会保留原值。Obsidian 核心的 **Templates: Insert template** 仍使用该 Vault 配置的共享模板目录，可以由你自行设置。建库预览按照模板声明初始勾选搜索排除目录。例如，本例默认勾选 `Templates`，新规则只匹配 `光学研究/Templates/`。排除后，Obsidian 搜索、关系图谱和依赖该目录的 Bases 视图可能隐藏模板。Kepano 默认不勾选 `Templates`，需要隐藏时可在预览中勾选。若已有全 Vault 的 `Templates/` 规则，它仍会生效，可在 Obsidian 的排除文件设置中核对。对于 2.2.0 创建的库，插件仍可读取已有共享模板；共享目录缺失时，可预览并将模板恢复到本库。

## 保存一次修改

在 `光学研究/Notes/` 写一条笔记。在右侧栏的「光学研究」行点击 **Git 工作区**，填写说明并点 **预览提交**，核对库路径、增删改、提交说明、作者和邮箱。保存后会显示 SHA，可在 **历史** 中查看。若已有暂存内容，按钮改为 **提交已暂存内容**。同一个文件在暂存后继续编辑时，本次提交保留原暂存版本，其余编辑留在工作区。

管理器中的操作以所在行确定目标。也可以从编辑中的笔记运行 **保存本库版本**、**查看本库历史**；插件无法从笔记定位知识库时会打开选择器。[逐库 Git 操作](library-git.md)
