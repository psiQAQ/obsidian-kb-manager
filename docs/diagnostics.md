# 运行和解读知识库检验

在桌面管理器打开目标库的 **… → 检验**。在 **运行检验** 页直接运行常规与模板专项。如果准备移动或克隆这个库，将检查范围切为 **自选检查项**，勾选 **可移植性** 后运行。历史记录和离线工具分别在 **历史报告**、**检验工具** 页。

| 想确认的事情 | 选择与结果 |
|---|---|
| 笔记、附件和清单能否正常使用 | 通用项检查清单与登记、属性语法、链接与嵌入、标题与块、Canvas、Bases 和受管绑定。报告按严重程度给出规则编号、文件和可用的位置。 |
| 单独搬走这个库会缺什么 | 可移植性列出已解析的跨库依赖。Canvas 的文件节点、分组背景、文本链接也在范围内；同名候选与实际目标分别标明。 |
| 内容是否符合所选模板的组织方式 | 选择模板声明的专项。比如新版知识花园会对拟分享笔记指向私有页面的链接发出警告。桌面使用 Obsidian 实际选中的目标。 |

桌面默认在本库和已登记库中查找同名候选。勾选 **在整个 Vault 查找同名候选** 可纳入其他文件夹，两种范围都会显示 Obsidian 实际解析到的目标。

同时看**严重程度**和**覆盖情况**。例如，图片引用已确认跨库，另一篇 Markdown 又无法读取，同一份报告会同时显示警告和「部分完成」。在 **各项检查范围** 查看原因，再按严重程度查看问题、文件位置和规则。离线短链缺乏 Vault 索引时也可能显示未验证。

选择 **查看报告 JSON** 可打开原始报告。选中所需文本或点击 **全选** 后，使用系统复制命令。

## 审查库内规则与更新工具

新实例的 `checks/common/` 保存可编辑的通用规则。以属性检验为例，桌面和离线工具都会执行本库的 `checks/common/properties.mjs`。官方摘要来自插件或独立工具自身。编辑文件后，桌面会在该项旁显示 **审查脚本**，可比较源码、核对 SHA-256 并授权这份内容。再次编辑会产生新的摘要。离线端使用 `--trust-digest` 传入已审阅的摘要。直接从命令行启动 `checks/kb-check.cjs` 时，须先信任入口文件本身。

已带工具的实例可以在检验界面比较已安装版本与插件分发版本，再确认更新。预览会标出已修改的文件，供手动合并。日常运行与插件升级都会保留这些修改。

## 专项脚本与日志

模板专项通过本机 Node.js 运行，脚本拥有当前系统账号的文件和网络权限。内置脚本按发行包中的摘要识别；个人脚本通过检查项旁的 **审查脚本** 查看源码和 SHA-256，再选择 **授权此版本**。脚本内容改变后需重新核对。请只运行你信任的脚本。

通用检验读取清单、笔记、附件引用及宿主提供的元数据，保留笔记内容、Git 暂存区和提交历史。新建实例会在默认由 Git 忽略的 `.log/` 保存每次检验的 JSON 报告；受管路径的修复在独立的预览中确认。模板专项须遵循只读约定。离线 agent 可调用 `kb-check.cjs` 并读取报告的 `status`、各项 `coverage` 和 `diagnostics`。[专项脚本协议](template-authoring.md)

## 离线运行与读取报告

3.2.0 起，新建库的首次提交包含 `checks/kb-check.cjs` 和 `checks/common/` 下的通用规则。进入实例根目录，在装有 Node.js 的机器上运行：

```sh
node ./checks/kb-check.cjs --library . --list
node ./checks/kb-check.cjs --library . --checks all
```

需要指定宿主 Vault 时加上 `--vault-root "<Vault 路径>"`；可移植性可单独用 `--checks portability` 检查。桌面与 CLI 都执行库内的规则。修改规则后，在桌面检验界面审查脚本并授权该版本。规则以运行 Node 的用户权限执行。旧库继续使用原有检验方式，可从 **… → 检验 → 检验工具 → 选择保存位置** 导出独立入口。

CLI 将报告作为单行 JSON 写到标准输出。若两库都有 `[[实验记录]]`，桌面可以查询 Obsidian 在当前来源页选中的目标；单选可移植性可查看同名候选。离线只有短链时，保留报告中的未验证原因。agent 即使收到退出码 0 也应读取报告，例如将上条命令的输出保存为 `report.json` 后运行：

```sh
node -e "const r=JSON.parse(require('node:fs').readFileSync('report.json','utf8')); console.log(r.status); for (const c of r.checks || []) console.log(c.id,c.status,c.coverage,c.diagnostics)"
```

退出码 1 表示报告含错误级诊断，2 表示运行或日志失败、脚本尚未授信，或参数无效。个人脚本可在核对实际文件后用 `--trust-digest` 指定认可的摘要；自定义 Vault 配置目录用 `--config-dir` 指定目录名。

运行检查、列出专项（`--list`）和读取历史（`--history`）都使用指定的 Vault 范围。若列出专项或读取历史时收到退出码 2，先核对 `--library` 是否位于 `--vault-root` 内，以及路径是否误指向 Vault 配置目录。
