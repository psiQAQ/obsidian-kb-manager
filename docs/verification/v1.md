2026-11-19 在 Windows、Obsidian 1.15.1 与隔离 Vault 验证。将 ZIP 中的全部文件解压安装，再从宿主加载插件。运行创建、提交和历史检查期间，测试探针将渲染进程 PATH 置空，结束后恢复。该实例的 Chromium 使用不可达代理，应用更新检查实际返回连接失败。没有改动系统网络设置。解压后的四个文件与交付 ZIP 逐字节一致。

## 平台与检查方式

- **Windows — Passed**。Node.js 24.19.0，10 项自动测试、类型检查、生产构建。ESLint 为零错误、一条设置页搜索集成建议。项目锁定的 Obsidian 类型版本为 1.12.3，设置使用实际验证过的命令式 API。
- **Linux 核心逻辑 — Passed**。WSL Ubuntu 24.04 的 Node.js 20.20.1 运行相同的十个测试。用已安装的 esbuild 转译 TypeScript，Linux 进程读取同一仓库中的测试目录，使用原生 Linux Git 和 Python 3。磁盘为挂载的 Windows 文件系统，未验证原生 ext4 上的桌面宿主。
- **macOS、Linux 桌面和托管 CI — Not Run**。本机没有 macOS 或 Linux Obsidian。三系统 CI 已配置到 checkout、依赖恢复、类型检查、lint、测试、构建和 ZIP 核验。本次只做本地提交。实际三系统运行结果仍是正式发布前的验收项。

## 结构体检与旧检查器

| 项目 | 插件行为 |
| --- | --- |
| 路径映射、入口和内容目录 | 读取 v1 TOML，检查边界、重叠、缺失和类型。 |
| 知识页来源、索引 Markdown 链接 | 检查本库可解析的相对文件路径。复杂 Markdown 引用、双链消歧和语义关联仍需人工或 Agent 核对。 |
| 来源快照 | 只读比较原笔记文件系统的纳秒时间与快照中的十进制字符串。Windows 和 WSL 分别用同一文件与 Python 的 st_mtime_ns 对照；变化报告人工复核。 |
| Bases | 检查已登记的过滤字段。可修复原表达式仍匹配的绑定；缺失的内置 v1 总览可从内置版本重建。自定义表达式只报告。 |
| 数字、直接引语、事实与证据充分性 | 留给人工或 Agent 逐项查原件；插件不生成或改写知识正文。 |

## 验证中出现的问题

首次运行 Windows 模板测试时，临时目录改名返回 EPERM。实现增加了有界重试，每次复核目标占用，随后 Windows 和 WSL 用例通过。恢复会话后，普通沙盒拒绝 Node 派生测试进程及 esbuild 服务；在普通用户账户下运行同一命令通过。首次实机探针完成提交后，因定位关闭按钮失败而中断，维护探针也曾因设置行定位失败而未执行。修正探针后，最终包通过上述桌面流程。
