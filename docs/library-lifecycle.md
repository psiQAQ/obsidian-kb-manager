# 接管、迁移和恢复知识库

## 整库迁移与身份冲突

- **复制或移动整库**。保留根目录的 `kb.toml`。在目标 Vault 导入这个文件，核对 ID、首页、位置、偏好和受管文件预览，再登记。用户改写过的绑定保留并提示复核。只从 Git 克隆时，可以补选原清单恢复原身份，也可以明确选择按新库接管。
- **找回登记**。登记表丢失时选择目录扫描，核对候选库后重建。原路径失效时，选择清单重新定位；同一 Vault 中的独立副本需要分配新 ID。重复身份解决前，相关库暂停写入。

## 文件和设置存放位置

| 文件或位置 | 内容 |
|---|---|
| 库根 `kb.toml` | 目录映射、身份、首页、模板、受管文件指纹，以及明确保存的逐库偏好。新库通过 `/kb.toml` 默认忽略它。整目录复制时请一并带走。 |
| 插件 `data.json` | `registeredLibraries` 保存已登记库的 Vault 相对路径，`language` 和 `defaults` 保存语言和全局 Git 默认值。文件位于当前 Vault 配置目录的 `plugins/knowledge-base-manager/` 下。 |
| Obsidian 设备本地存储 | 建库父目录、自定义模板目录、自动操作授权和未完成操作的恢复信息。在新设备上重新确认自动操作。 |
| 库内 `.git/config`、系统 Git、SecretStorage | 库级 Git 身份与远端由 Git 管理，认证由系统或选定的 SecretStorage 凭据提供。 |

从 2.0 升级后，可在全局设置中核对旧版逐库偏好。确认库 ID、目标清单和值，再将选定库的覆盖写入 `kb.toml`。旧授权需在本设备核对后恢复。

## 归档、目录改名和中断恢复

- **编辑显示名或简介**。打开知识库的 **… → 编辑**，修改字段后点 **直接应用** 即可保存。想先核对内容时，点同一行的 **预览变更**。左侧是变更前的值，右侧是变更后的值；窄窗按字段依次显示。点 **应用变更** 保存，按 Esc 可返回继续编辑。
- **归档或恢复活动**。在编辑页的状态区域选择相应操作，核对本次要写入的字段后确认。归档后仍可打开知识库并查看历史。
- **目录移动或改名**。打开库行菜单 **… → 移动**，选择 Vault 根或已有的目标父目录。选回原父目录并修改目录名即可改名。点 **预览目录移动** 可对照源目录、目标目录和受管文件的变更，并核对搜索排除规则。确认后，管理器移动整个目录及其中的 Git 数据，更新登记路径，并迁移插件创建的排除规则。

如果自己写的 Base 使用了旧目录，在移动预览中逐项核对文件、筛选字段、原值和新值，勾选希望随库更新的字段。这些选项初始为空，同一文件可以只改一处。比如把 `课程甲` 改为 `课程乙`，可只更新 `file.inFolder("课程甲/Courses")`，保留另一个筛选条件和表格列宽。笔记里内嵌的 Base 也按字段选择。完成这次移动后，文件继续由你维护。
- **选择引用**。预览按所属库和 Vault 未登记区域列出可更新的文件。比如把“光学研究”改名为“实验笔记”，可以勾选另一个库中引用光学笔记的读书卡，保留未勾选的文件。Obsidian 启用“自动更新内部链接”时，预览会预选移动库自身的引用。其他库和未登记区域分别勾选。确认前展开文件列表，检查需要人工核对的同名链接、动态查询和外部剪藏。支持已解析的 Wiki 与 Markdown 链接、标题与块、附件和 Canvas 文件节点。

  **随移动更新**列出已纳入受管更新的字段。**路径保持有效**收起已核实的属性与引用式链接，展开可查看原引用和移动后的目标。**需人工核对的引用**列出跨库依赖、同名候选、缓存与原文不一致及受管更新未覆盖的引用。先保存打开的笔记，再重新预览以核对最新内容。
- **中断恢复**。选择管理器中的 **复核并继续**。管理器会核对库 ID、Git 状态、已选文件及其内容，再继续剩余步骤。若文件在预览后被编辑，请先核对提示中的路径和自己的修改。

## 给旧库启用专项检验

旧库可直接运行通用检验。对于 2.4.0 及更早版本创建的融合 LLM Wiki 或 Kepano，打开 **… → 预览清单升级**，展开 `checks/` 下的脚本和 `kb-template.json` 查看内容与 SHA-256，再选择 **应用清单升级**。升级保留原库 ID 和偏好，并将 `.log/` 加入本库 Git 忽略规则。若同名脚本或声明已有个人改动，预览会列出需要人工核对的文件。

可先运行通用项核对现状，检查结果及日志位置见[运行知识库检验](diagnostics.md)。
