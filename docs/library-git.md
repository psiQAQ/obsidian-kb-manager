# 在侧栏管理本库 Git

## 查看改动与提交

点击书架图标或运行 **打开知识库管理器**。在「光学研究」行点击 **Git 工作区**，或从行菜单打开它。展开另一个库时，侧栏会收起前一个库。切回时仍能看到该库刚才输入的提交草稿。文件行区分已暂存和工作区改动，可以预览差异、单独暂存或撤销暂存。历史按钮在编辑区打开本库的提交图。归档库仍能阅读历史。

侧栏可以按树或列表查看变更，预览文件或差异块后选择要暂存的范围。如果同一个文件同时有已暂存和未暂存修改，**提交已暂存内容** 只提交预览时的暂存版本，之后的编辑继续留在工作区。命令面板中的 **保存本库版本** 和 **查看本库历史** 可从当前笔记进入对应仓库。

## 阅读文件差异与提交图

在「工作区更改」中点文件名，比较暂存区与磁盘上的文件；在「已暂存的更改」中点同一文件，比较上次提交与暂存区。再次点同一项会回到已有标签。双栏按行对照旧文和新文，统一视图按顺序列出增删。绿色 `+` 表示新增，红色 `−` 表示删除。

在 **Git 工作区 → 历史** 中，默认显示当前分支可达的提交。查看尚未合并的工作时，切换到所有分支范围，图中会包含本地已有的远端跟踪分支。点选提交可查看正文和变更文件；合并提交可选择父提交，再点文件查看相应差异。

在历史页按 `Ctrl+F`（macOS 为 `Cmd+F`）可按提交 SHA、标题、正文或作者查找。搜索覆盖所选范围内尚未翻到的提交。

## 配置身份、偏好和远端

设置首页的 **界面语言** 支持跟随 Obsidian、简体中文和 English。全局 Git 设置按分类打开。在知识库行点击 **… → 本库 Git 设置** 可覆盖个别选项，使用恢复按钮重新继承。库目录移动后，同一 ID 继续使用原偏好。

在知识库目录执行 `git config --show-origin --get user.name` 和 `git config --show-origin --get user.email` 可核对身份来源。若要为「光学研究」使用单独的署名，打开 **本库 Git 设置 → 身份与凭据**，预览后写入该库的 `.git/config`。清空其中一项并保存，即恢复该项继承。姓名和邮箱会随提交进入 Git 历史。如果另外设置的作者、提交者或环境变量使实际身份与预览不同，插件会在暂存前提示使用命令行完成该提交。修订已有提交会保留原作者。

在 **Git 工作区 → 远端与分支** 配置 HTTPS 或 SSH 地址及上游分支。桌面 HTTPS 默认使用系统 Git 凭据助手，SSH 使用本机 SSH 配置与代理；也可以为指定知识库和 HTTPS 目标明确选用 Obsidian SecretStorage 中的令牌。推送前核对目标，推送会发送本库提交历史。如升级后旧的自动推拉授权显示已暂停，打开本库的时钟按钮，核对远端和授权范围后再启用。

桌面 Git 默认通过系统 PATH 查找。Windows 可运行 `where.exe git` 查看已安装的位置；需要指定时，在 **设置 → Knowledge Base Manager → 高级** 填写 Git 可执行文件的绝对路径，只保存在本设备。Vault 根仓可继续使用 Obsidian Git。[功能对照](git-compatibility.md)

## 处理冲突和写入受限

原生变基需要干净的工作区和暂存区。如果变基中断，请先在该知识库的目录用 Git 完成或中止变基。普通合并冲突可以直接在笔记中预览并选择保留的内容，再回到本库面板明确暂存解决结果。

本地 Git 写入目前支持普通自包含仓库。遇到 Git 锁、冲突、linked worktree、过滤器或尚未兼容的索引布局时，界面会报告原因。插件卸载后库目录、Markdown、附件和 `.git/` 均可独立使用。

从头创建仓库和查看首提交的步骤见[安装与建库](getting-started.md)。
