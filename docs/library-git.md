# 在侧栏管理本库 Git

## 查看改动与提交

点击书架图标或运行 **打开知识库管理器**。首次打开位于右侧栏，之后会激活管理器当前所在的侧栏、编辑区或独立窗口。Obsidian 恢复工作区布局时，管理器同时恢复选中的库、展开状态和标签页。

在「光学研究」行点击 **Git 工作区**，或从行菜单打开它。展开另一个库时，管理器会收起前一个库。切回时仍能看到该库刚才输入的提交草稿。文件行区分已暂存和工作区改动，可以预览差异、单独暂存或撤销暂存。历史按钮在编辑区打开本库的提交图。归档库仍能阅读历史。

侧栏可以按树或列表查看变更，预览文件或差异块后选择要暂存的范围。如果同一个文件同时有已暂存和未暂存修改，**提交已暂存内容** 只提交预览时的暂存版本，之后的编辑继续留在工作区。命令面板中的 **保存本库版本** 和 **查看本库历史** 可从当前笔记进入对应仓库。

在终端暂存或提交后，切回 Obsidian 窗口。开启 **自动刷新 Git 状态** 时，管理器会在设定的延时后核对当前笔记、历史标签或已展开知识库的 Git 索引和引用。状态变化会刷新该库的工作区、打开的历史与差异、编辑器差异标记。已输入的提交说明和历史搜索词会随视图保留。

## 阅读文件差异与提交图

在「工作区更改」中点文件名，比较暂存区与磁盘上的文件；在「已暂存的更改」中点同一文件，比较上次提交与暂存区。再次点同一项会回到已有标签。双栏按行对照旧文和新文，统一视图按顺序列出增删。绿色 `+` 表示新增，红色 `−` 表示删除。

在 **Git 工作区 → 历史** 中，向下滚动即可加载更早的提交。要看两个尚未合并的分支，打开范围选择器，选 **所选引用**，勾选这两个分支。**所有引用** 还包括已获取的远端跟踪分支和指向提交的标签。工具栏可以跳回 HEAD、刷新历史或调整显示。按 `Ctrl+F`（macOS 为 `Cmd+F`）可查找 SHA、提交说明、作者、引用名或显示日期，包括尚未滚动到的记录。

单击一条提交，默认在该行下面展开。左栏显示提交 SHA、父提交、作者、提交者、日期和完整提交说明，右栏列出本次变更的文件。普通提交与父提交比较，合并提交默认与第一父提交比较，首次提交显示从空树开始新增的文件。绿色标记表示新增，红色标记表示删除。已修改文本文件名后的 `(+10|-5)` 表示新增 10 行、删除 5 行。点击文件打开逐行差异，再次点击同一提交收起详情。可在 **图谱显示设置 → 详情位置** 改用底部或右侧面板。

例如，要比较「整理文献」和「补全引文」，先点「整理文献」，按住 Ctrl（macOS 用 Cmd）点击「补全引文」。面板留在「整理文献」下面，两条提交都会标出。继续按住 Ctrl/Cmd 点第三条，会用第三条替换「补全引文」；再按住 Ctrl/Cmd 点当前比较对象，回到「整理文献」本身的详情。默认从图中靠下的提交比较到靠上的提交，按相反顺序点击也会得到相同的增删方向。核对两个 SHA，需要时点 **交换比较方向**。

要持续以某个版本为起点，可选 **设为比较基线**。文件行菜单可打开只读历史版本或恢复预览。比较两个固定版本时，已审阅的文件会在本设备保留标记。**与工作区比较** 会一起显示已暂存、未暂存及未跟踪的变化。要看暂存边界，可从侧栏分别打开。

在图上右击提交或引用，或点击详情的 **更多操作**。从旧提交新建分支时，确认框显示起点 SHA。合并提交可选不同父提交作为比较基线。要摘取、撤销、重置或恢复文件，先查看预览中的知识库路径、引用、提交及受影响文件。发生冲突时，先编辑文件，再在 **继续或中止操作** 中逐个标记解决结果。高级操作的适用范围、与 Git Graph 的差别及实现入口见[桌面历史图功能对照](git-graph-compatibility.md)。

## 配置身份、偏好和远端

设置首页的 **界面语言** 支持跟随 Obsidian、简体中文和 English。全局 Git 设置按分类打开。在知识库行点击 **… → 本库 Git 设置** 可覆盖个别选项，使用恢复按钮重新继承。库目录移动后，同一 ID 继续使用原偏好。

Obsidian 通报插件 `data.json` 被同步或外部编辑时，管理器重新加载全局偏好和知识库登记表。编辑已登记库的 `kb.toml` 后，该库的显示名称、路径映射和 Git 偏好也会重新核验。

在知识库目录执行 `git config --show-origin --get user.name` 和 `git config --show-origin --get user.email` 可核对身份来源。若要为「光学研究」使用单独的署名，打开 **本库 Git 设置 → 提交身份 → 查看或修改**，填写姓名或邮箱，点 **直接应用** 写入该库的 `.git/config`。清空一项即可恢复继承；想先核对实际生效的值及来源，可点 **预览变更**，再点 **应用变更**。姓名和邮箱会随提交进入 Git 历史。如果另外设置的作者、提交者或环境变量使实际身份与预览不同，插件会在暂存前提示使用命令行完成该提交。修订已有提交会保留原作者。

在 **Git 工作区 → 远端与分支** 配置 HTTPS 或 SSH 地址及上游分支。桌面 HTTPS 默认使用系统 Git 凭据助手，SSH 使用本机 SSH 配置与代理；也可以为指定知识库和 HTTPS 目标明确选用 Obsidian SecretStorage 中的令牌。推送前核对目标，推送会发送本库提交历史。如升级后旧的自动推拉授权显示已暂停，打开本库的时钟按钮，核对远端和授权范围后再启用。

桌面 Git 默认通过系统 PATH 查找。Windows 可运行 `where.exe git` 查看已安装的位置；需要指定时，在 **设置 → Knowledge Base Manager → 高级** 填写 Git 可执行文件的绝对路径，只保存在本设备。Vault 根仓可继续使用 Obsidian Git。[功能对照](git-compatibility.md)

## 处理冲突和写入受限

启动变基前，请先提交或贮藏当前更改。普通变基、合并、摘取或撤销提交遇到冲突时，可以编辑各个文件，在本库面板标记已解决，再继续或中止操作。含自定义重放指令的交互式变基，请回到发起变基的 Git 客户端完成。

本地 Git 写入目前支持普通自包含仓库。遇到 Git 锁、冲突、linked worktree、过滤器或尚未兼容的索引布局时，界面会报告原因。插件卸载后库目录、Markdown、附件和 `.git/` 均可独立使用。

从头创建仓库和查看首提交的步骤见[安装与建库](getting-started.md)。
