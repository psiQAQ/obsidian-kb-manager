# 知识库操作规则

## 适用范围与入口

操作前确认目标库，读取本库 README、`kb.toml` 和适用的 Vault 规则。所有相对路径以本库为准。缺少目录映射或必要结构时报告缺项。

默认只读写已指定的知识库；跨库须明确授权。规则变更须用户同意。独立迁出共享 Vault 时先说明共享工具、Bases 和属性双链需适配，不能据此扩大读写范围。

## 内容所有权

- 原始资料位于映射的 `raw/` 与可选 `Clippings/`。已接收原件不改内容、不改名、不移动、不删除；缺失元数据在摄入日志补充。剪藏保留原位，不移入 raw 或“已摄入”目录，不当作错放人工笔记。
- 新获取资料以原始标题命名，仅处理非法字符与同名冲突；记录来源 URL、收集日期和已知发布日期，不猜测日期。已有 Clipper 的 `source`、`clipped` 等字段原样保留。保存网页的新版本另建文件，不覆盖或追加到旧原件。
- 生成知识位于映射的 wiki，标记 `managed_by: agent`。未明确标记的已有内容按人工内容保护，不能仅因位于 wiki 而改写。
- 人工笔记统一放在本库 `Notes/`。用户已明确目标库时，可以整理错放笔记的位置、修复受影响链接、按模板补齐缺失属性；保留正文观点、个人评价及已有属性。未知作者、创建日期或标签含义不臆填；歧义、重名或跨库影响先报告。raw、Clippings、项目文档、模板与上游示例不属于错放笔记。
- 人工笔记允许有意未创建链接，不据此删链或建页；生成知识的引用与导航必须可解析。
- 附件保存在本库，原始资料附件随原件，人工笔记附件放在笔记旁 `assets/`。远程图片链接不等于已下载，离线保存须核对实际文件。展示人工笔记不授予改写权限。

## 摄入流程

1. 确定目标库及资料范围。单份先讨论要点与拟更新位置，已确认的目标和处理方式不重复询问；明确批量则逐份串行完成，疑点保守处理并汇总。不得自行创建定时任务。
2. 读取已有原件或保存新来源；PDF、图片和人工笔记按下面的专门流程准备。用实体、同义词及相关说法搜索本库索引和全文，判断 `New`、`Update`、`Disputed` 或 `No material`。前三者可组合，后者独立。
3. 有新增知识或争议才建立资料摘要并更新知识页；`No material` 保留原件、只记日志，不强行生成摘要。独立实体或概念页须由原文单独成节或重点论述支撑，零散提及归入相关页；此限制不适用于人工思考笔记和纯类别导航。
4. 同一核心论点合并更新，检查全库受影响的 Agent 管理知识，不只看索引；重要全局变化更新综述。原件、个人笔记与历史归档不参与内容级联更新。
5. 真实来源分歧并列保留并各自引用，不自行化解。“较晚发布”不等于推翻旧资料。确有可靠资料明确取代旧结论时，正文采用现行说法，注明替代来源和日期；重要旧说法保留简短历史，一般旧版通过 Git 查询。
6. 对照原文逐条复查本次事实，检查属性、来源、目录和链接。更新知识索引，为本次操作新建日志，并在日志入口加入链接。原件留原位。单份通常只记日志；批量写独立报告，列处理结果、未读文件及原因、疑点和待确认事项，不把跳过或读取失败当成无新增内容。

只有用户明确要求研究、检索补充资料时才联网研究并走摄入流程；普通知识问题走查询，体检发现空白只给研究建议。搜索可并行，编译、共享索引、日志及级联更新串行进行。

## PDF 与图片资料

先保留原始 PDF 或图片，不修改、压缩替换或用识别文字覆盖原件。有可用文字层的 PDF 优先使用当前环境已有工具读取；确需识别图像时才调用当前会话可用的 `local-ocr` Skill，先读其 SKILL.md 并执行可用性检查，再按文档处理扫描 PDF、整页图片或公式。该 Skill 是可选本机能力，不保证每个使用本模板的环境均已安装。

- 转换中间文件放在本库已确认忽略的 `.cache/`。原件与需要长期引用的提取文字分开保存；正式提取稿放入 raw，注明对应原件、页码范围、提取日期、方法及识别不确定处，所需图片保存在同库 assets。未校对结果不得冒充原文。
- 阅读返回状态和逐项结果，核对公式、表格、关键数字、日期和引语。部分失败保留可用结果并报告缺页或失败项；缺工具、依赖或模型时说明具体条件，不隐式安装或下载，也不把失败解释为空白资料。
- 生成页引用实际使用的原件和提取稿，并给出可复核页码。提取稿中的原件对应信息用于追溯，不单凭 OCR 字符匹配认定事实正确。新版本另存，不覆写已作为证据使用的提取稿。
- 检查器不解析 PDF、图片，出现 `evidence-unverified` 时另行阅读原件核查，并在交付中说明核查方式；必要来源保留原引，并注明人工复核的范围。
- 视频网页只按实际取得的页面文字处理；需要视频内容时另行取得授权范围内的字幕或转写，记录视频出处及时间位置。不能仅凭视频链接、标题或简介声称读过完整内容。

## 个人笔记摄入快照

明确要求把指定个人笔记编译为知识时，才执行此流程；普通查询、位置整理和体检不批量复制 Notes。

1. 原笔记保留在 Notes，不改观点或已有属性。在 raw 新建“笔记标题 - 摄入快照 YYYY-MM-DD.md”；同日重名加数字后缀，不覆盖。
2. 保留笔记内容，另列原笔记的库内路径、快照日期和选取范围，明确其为个人记录。所需本地附件复制到快照旁的 assets 中并按来源区分名称，只调整快照里必要的附件路径；原笔记及附件不动。引用缺失、歧义或跨库时报告，不扩大复制范围。记录快照在本次摄入日志中。
3. 知识页的 `sources` 引用该 raw 快照；原笔记可作相关阅读链接，但不作为检查器的来源路径。个人经验、猜测和评价按其性质呈现，不因进入 wiki 就变成已核实的外部事实。
4. Notes 后续编辑不自动改写快照或知识页。用户再次要求摄入时新建快照，与旧版比较后更新生成知识；旧快照保留供追溯。

新建快照时，在来源属性中记录 `snapshot_source_note`（相对快照文件、指向本库 Notes 原笔记的路径）和 `snapshot_source_mtime_ns`（摄入时原笔记的 `st_mtime_ns`，带引号的十进制字符串）。例如快照位于 raw 时：

```yaml
snapshot_source_note: "../Notes/读书想法.md"
snapshot_source_mtime_ns: "1794873600000000000"
```

时间应取自读取原笔记时文件系统返回的实际纳秒修改时间；取值前后原笔记若被编辑，重新读取并记录。两项在共享属性类型中均为文本，不转换成浮点数字。快照日期、选取范围及附件保全仍须记录。

检查器只对现行知识引用的 raw 快照核对这些字段，并按原笔记汇总“可能需要重新摄入”。缺失原笔记、字段不完整或无法核验分别报告 `REVIEW`；越界路径不跟随。复制、还原和 Git 检出也可能改变修改时间；时间相同不证明内容未变。旧快照没有这两个字段时保持兼容，不自动补写、不计算哈希，也不自动更新快照或知识页。

## 页面格式与证据

生成页正文和文件名以中文为主。专名有通行译名时使用“中文名 原名”，否则保留原名。资料摘要使用“资料摘要 - 原标题”，与原件区分；同名增加有意义的区分或数字后缀，不覆盖。

使用 YAML frontmatter 和简短英文键：

| 属性 | 写法与用途 |
| --- | --- |
| `type` | 知识类型为 `source`、`entity`、`concept`、`analysis`、`archive`、`overview` 或 `category`。`raw`、`note`、`index`、`log`、`operation`、`report`、`document`、`dashboard` 等类型用于其他页面。 |
| `managed_by` | 生成知识用 `agent`，人工笔记用 `human`；未标记已有内容仍受人工内容保护。 |
| `categories`、`tags`、`aliases` | 字符串列表。分类与标签先复用、确需再扩展；英文用复数，中文自然表达，不设固定白名单。 |
| `created`、`updated` | `YYYY-MM-DD`。`updated` 只随知识内容变化刷新，不因排版修改刷新。 |
| `sources` | 带引号的内部链接列表，指向本库原始资料。归档引用生成答案所用的知识页。旧库的相对文件路径仍可读取。 |
| `archived` | 归档日期，保留在页面属性中，不要求复制到索引。 |
| `source_url`、`collected`、`published` | 新来源的 URL、收集日期及已知发布日期；Clipper 原件的 `source`、`clipped` 保留原名和原值，不批量统一。 |

`sources` 和 `related` 使用带引号的双链，每条写出从 Vault 根开始的完整路径，例如 `"[[示例父目录/研究示例/raw/实验记录.pdf]]"`。`sources` 已提供完整来源时，正文只在需要定位具体出处时补充页码、章节或段落链接。双链的写法见 [Obsidian 属性文档](https://obsidian.md/help/properties#List)。

正文与导航使用 Markdown 相对链接。同目录或子目录目标以 `./` 开头，父目录用 `../`，空格等字符用 URL 编码。章节片段使用实际标题文字，空格写 `%20`。已有人工链接保持原有格式。

每一条事实陈述须有可追溯依据。关键数字、日期和直接引语写入前定位原文，保留原始数值写法；计算列出组成值。推断、归纳和解读标明“非原文／推断”并给依据。原文之外的外部事实须先取得并保存来源，不能只加标签。工作记忆、旧日志及模型训练知识不能替代来源。

## 查询、保存与归档

- 普通查询先读本库索引，再按关键词及同义词全文搜索；阅读相关页并带引用回答，不写页面或日志。只有索引和全文检索均无结果才说明未发现相关内容，并交代搜索范围。
- “保存”创建可持续维护的分析页；“归档”创建带日期的历史快照。两者均更新索引和日志，同名不覆盖；用户明确要求更新已有分析时才合并。
- 保存分析的事实追溯到本库原始资料；归档的 `sources` 链接当时使用的知识页。归档不随新来源改写内容；来源知识更新后可报告可能过时，可修复有确定目标的断链，不改历史观点。

## 体检与修复

根据原文修复 Agent 管理知识的结构、索引、有效链接、事实、未标推断、过时说法和缺失交叉引用，并按建页标准补页。没有确定目标或可靠依据的事项只报告，不猜测修复；真实资料分歧保留。

人工笔记只执行位置、缺失属性及链接整理例外，不替用户复盘或给个人评价；原始资料与规则文件不动。资料空白只列研究建议，不自行联网或建立定时任务。

修复后复查，在 reports 对应目录写报告，列问题、修复、改动页面、未解决事项及原因，在日志链接报告。同日多次报告用时间区分，保留操作记录。机器检查只提供线索，仍须完成受影响内容的语义复核。

## 索引与日志

`wiki/index.md` 按主题用普通 Markdown 列表收录知识页，每个条目给一个链接和一句摘要。归档摘要以 `[Archived]` 开头。知识更新时间和归档日期在页面属性或 Bases 中查看。旧索引可保留原有表格。页面日期、索引遗漏、重复与断链仍需检查，综述在形成有依据的综合认识时更新。

```markdown
- [对照实验](./对照实验.md) — 列出对照条件与观察结果。
- [首次方案比较](./首次方案比较.md) — [Archived] 保留当时对两种方案的判断。
```

`wiki/log.md` 是操作日志入口。每次实际执行的 `ingest`、`save`、`archive` 或 `lint` 在 wiki 的 `logs/` 下建一篇独立日志，使用“操作日志模板”，再在入口加入相对链接。文件名使用“日期 - 操作 - 标题”，同名时用时间或数字后缀区分。普通查询不记日志。既有内联日志和独立日志共同保留历史。

例如，在 `wiki/logs/2026-11-16 - ingest - 对照实验.md` 记录一次摄入。

```yaml
---
type: operation
managed_by: agent
date: 2026-11-16
operation: ingest
disposition: New
sources:
  - "[[示例父目录/研究示例/raw/实验记录.md]]"
related:
  - "[[示例父目录/研究示例/wiki/对照实验.md]]"
---
```

入口链接写成 `- [2026-11-16 摄入对照实验](./logs/2026-11-16%20-%20ingest%20-%20对照实验.md)`。正文可以记录处理细节和待办。`sources` 收录实际使用的本库 raw 或已映射 Clippings 原件，`related` 收录本次变更的知识页或对应报告。批量摄入和体检在 `related` 链接各自报告。`No material` 单独用作 `ingest` 的 `disposition`，至少填一个能解析到原件的 `sources` 链接，供待摄入清单识别。

## 分类入口与 Bases

保留全库 `knowledge.base` 总览，按需建立独立类别入口及专用 Base，不预装完整生活分类。视图的候选页面与打开或嵌入上下文均限定所属知识库，跨库或未知上下文显示空结果。Bases 不读取 `kb.toml`；修改库名、目录映射或类别页名称时，同步检查过滤条件、属性链接和嵌入，不只依赖自动更新链接。

Knowledge Base Manager 创建内置 LLM Wiki 实例时，会把总览绑定到实际库根、wiki 与 Notes。人工复制时，仅在新库的 `knowledge.base` 中填写 `__KB_ROOT__`、`__WIKI_PATH__`、`__NOTES_PATH__`：均为从 Vault 根起的完整路径，例如 `示例父目录/研究示例`、`示例父目录/研究示例/wiki`、`示例父目录/研究示例/Notes`，不加末尾斜杠。先确定 `kb.toml` 映射，再填绑定；公共样板保留占位符并显示空结果，实例遗漏则由检查器报告 `base-binding-missing`。不要批量替换整个知识库。

路径先按 Bases 表达式字符串转义，再按外层 YAML 转义：双引号写作 `\"`，YAML 单引号字符串内的 `'` 写作 `''`；中文与空格原样保留。插件实例化内置模板时会完成两层编码。默认“现行知识”与“按类别浏览”仅接受 wiki 内 Agent 管理的现行知识，排除 `status: empty` 的空综述、来源层、Notes、reports 和模板；“历史归档”只显示 wiki 内 `type: archive`，按 `archived` 降序。人工笔记视图只接受本库 Notes。

以默认布局的 `示例父目录/研究示例/` 建立“方法”入口为例：

1. 在 `wiki/方法.md` 使用“分类入口模板”，填写标题与日期，设 `type: category`。纯导航可保留空 `sources`；事实性说明仍须来源。入口可写导读和阅读顺序，不受独立事实文章的建页阈值限制。
2. 创建 `wiki/bases/`，复制 `Templates/Bases/分类专用模板.base` 为 `wiki/bases/方法.base`，不覆盖已有文件。
3. 填完全部 Base 占位符：`__KB_ROOT__` 为 `示例父目录/研究示例`，`__WIKI_DIR__` 为 `wiki`，`__TEMPLATES_DIR__` 为 `Templates`，`__CATEGORY_PATH__` 为 `示例父目录/研究示例/wiki/方法`（不含 `.md`）。按实际映射替换，统一 `/` 且不加末尾斜杠；引号按 Bases 表达式及 YAML 规则转义。
4. 在插入模板后的入口页，将 `{{base_path}}` 改为 `示例父目录/研究示例/wiki/bases/方法.base`。成员页的 `categories` 列表包含 `"[[示例父目录/研究示例/wiki/方法]]"`，不用跨库歧义短名。
5. 入口加入本库索引，记录本次操作日志。可调整列、排序和视图，不能移除范围与类别过滤。默认仅显示生成知识，展示人工笔记前另行约定范围，并明确限制在本库 Notes。
6. 在 Obsidian 打开入口与 Base，检查仅显示本库该类别，其他类别及其他库同名类别不出现，跨库嵌入为空。检查器不执行 Base 表达式，不能代替实际显示验证。

库改名或目录映射变化时，先核对目标库范围和现有修改，再更新映射、README、索引与链接；总览中的固定库根、wiki、Notes 路径以及分类 Base 的全部绑定必须同步调整。随后运行检查器，再实测直接打开、同库嵌入、跨库嵌入及侧栏切换。检查器不执行表达式，旧绑定即使没有占位符也可能指向错误目录。已有库升级应单独取得授权并逐项比较规则、模板和绑定，不覆盖人工内容。旧库启用 Clippings 时在授权范围内创建目录并加 `paths.clippings` 映射，不移动既有原件。浏览器扩展保存位置也须另行更新。

## 检查与交付

在 Obsidian 打开 Knowledge Base Manager，在目标知识库行选择 **… → 体检**。按文件查看发现与需复核的事项。区分确定的结构错误、仍待核对的内容和无法读取的来源。运行中断时复查目录和访问条件，再对同一库重试。

检查覆盖属性、目录、索引、链接、来源范围、未处理资料、Base YAML 及最小外层结构，以及部分数字写法、ISO 日期和较长直接引语。短整数、改写引语、定性陈述、计算与推理仍需阅读核实；字符串匹配不证明上下文成立。PDF、图片及 Base 表达式和实际显示须另行核查，禁止为消除提示而放宽证据要求。

非来源层的 `.base` 进行安全 YAML 解析：空文档允许，非空顶层须为映射，`views` 若存在须为映射列表，顶层和视图的 `filters` 若存在须为字符串或映射；格式问题报 `invalid-base` ERROR。不执行表达式、不限制插件扩展字段，也不完整校验嵌套过滤语义。模板样板允许绑定占位符，实例仍检查未填绑定；来源原件不套用这些检查。

旧库未配置 `paths.clippings` 时，若库根 `Clippings/` 含非占位文件且未被其他映射用途覆盖，按目录报一次 `clippings-unmapped` REVIEW。该目录不再作为错放人工笔记检查，但也不会自动成为合法来源；确认映射后另行启用，不移动或修改原件。只有占位文件时不提示。

人工内容中缺失的本库 Markdown 或双链目标统一提示 `REVIEW`，可能是待建页面，也可能是断链；不自动删链或建页。人工短双链另按页提示实际解析范围未核验：检查器只在本库查找，不读取其他库或 Vault 全局解析缓存。生成知识、索引、日志和 reports 导航缺失目标仍为 `ERROR`；README、规则与许可中的共享管理入口不套用库内导航限制。

正文、索引、日志和报告支持普通 Markdown 链接、单行引用定义、完整引用 `[显示文字][标签]`、折叠引用 `[标签][]` 及对应图片。引用标签按 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/#link-reference-definitions) 忽略大小写并合并空白，同名定义取第一条；快捷引用、多行定义及复杂嵌套不保证完整解析，仍须在 Obsidian 核验。证据候选保留链接显示文字，排除定义中的路径、网址与代码示例。目标先匹配准确文件，再尝试追加 `.md`，标题里的点号不替换为扩展名。

正文生成约定仍是显式 `./`、`../` 和实际标题文字。当前检查器把所有本地相对 Markdown 路径按当前文件目录解析，也接受部分 GitHub 风格标题 slug；裸路径、slug 和特殊字符库名的实际 Obsidian 解析尚未完整验证，静态通过不能证明界面解析一致。孤立页、缺失概念和语义性交叉引用仍需人工或 Agent 体检，不属于自动检查覆盖范围。

完成后列出最新页面与来源入口、实际处理范围、检查结果和剩余事项。用 `Passed`、`Failed`、`Not Run` 区分静态检查、实际运行及人工验收；解释失败或未运行的原因和影响，不把读取失败当作无新增内容。按适用 Git 规则仅提交本次变更，原件及历史快照保留，普通查询不提交；清理本次确认无用的小型中间产物，保留长期引用的来源与附件。
